# mirai — 用户指南

[English](GUIDE.md) | 简体中文

Linux 上的围棋棋盘，对接 KataGo：实时分析、SGF 棋谱的复盘与编辑，以及与电脑对弈。引擎可以跑在本机，也可以跑在你网络上的另一台机器上。

## 1. 安装

从 AUR 或源码安装见 [README 安装](../../README.zh-CN.md#安装)。`mirai` 是棋盘。`mirai-server` 是可选的，只有要把引擎放到另一台机器上时才需要（[第 7 节](#7-使用远程引擎)）。

### 需要从 KataGo 准备什么

请自行提供较新的 KataGo 程序（`katago`）和权重（`*.bin.gz`）；mirai 不会下载它们。它会根据你在首选项里的设置生成 KataGo 的分析配置。要用自己的，选择**首选项 → 引擎 → 分析配置 → 自定义文件**；KataGo 在其 `configs` 目录里附带一份 `analysis.cfg`。

mirai 驱动的是 KataGo 的 JSON **分析**引擎，绝不是 GTP——只讲 GTP 的机器人或包装脚本无法使用。如果你已经在 Lizzie、KaTrain 或 Sabaki 下跑 KataGo，把 mirai 指到同一份程序和权重即可；你的文件不会被复制或修改。

棋盘从 2×2 到 19×19，与原版 KataGo 构建一致。

## 2. 首次运行

如果 `katago` 在 `PATH` 上，并且找到了权重，mirai 会创建并启动一个 `local-default` 配置。第一次 OpenCL 启动可能要几分钟；见[疑难解答](#首次启动需要数分钟)。

权重的查找顺序是 `$XDG_DATA_HOME/{katago,mirai}/models`、`~/.katago/models`，然后是每个 `$XDG_DATA_DIRS` 条目下的 `{katago,mirai}/models`。同一目录里较新的 `*.bin.gz` 优先。最先找到的用来建立 `local-default`；其余可在首选项的模型选择器里选用。

如果没有找到 KataGo 或权重，分析页会显示**尚未配置引擎**，并带一个**首选项**按钮；首选项不会自己打开。棋盘和导航仍然可用，已存储的分析在没有实时引擎时也看得到。实时分析、全盘分析和形势判断在引擎启动之前保持灰色不可用；引擎启动过程中即可打开实时分析，其余两项要等引擎就绪。

### 添加本地引擎

1. 在**首选项 → 引擎 → 添加本地引擎**中，为配置命名，并选择 **KataGo 程序**和**神经网络模型**。模型选择器列出已发现的权重；文件夹按钮接受任何其他文件。两条路径都必须存在。
2. **分析配置**留在**由 mirai 管理**，或选择*自定义文件*以提供你自己的。它的选择器列出 `$XDG_CONFIG_HOME` 和 `$XDG_CONFIG_DIRS` 下 `{katago,mirai}/cfg/analysis` 里的 `*.cfg` 文件。
3. **搜索**和**批处理与内存**留在 **0**，即 mirai 的默认值（[设置参考](#引擎)），然后**保存配置**。

第一个添加的配置会立即启动；之后添加的不会改变当前选择。用引擎按钮切换。删除配置只去掉它的设置，不删除程序、权重或配置文件。

## 3. 界面

标题栏用来从野狐、弈城或弈客，以及文件或剪贴板打开棋谱，开始对局，以及切换引擎配置。棋盘导航栏上有编辑工具的开关。侧边栏有**分析**、**棋谱树**和**注释**页。对局进行时会藏起复盘导航、胜率图和侧边栏，直到终局；侧边栏会恢复成你离开时的样子。

胜率图始终从黑方视角绘制；分析侧边栏按行棋方来读。实线是黑方胜率，虚线是黑方目差，底部的条标记问题手。点击或拖动胜率图可沿主线跳转。拖动分隔条可调整高度；mirai 会记住这个高度。<kbd>g</kbd> 切换胜率图，<kbd>F9</kbd> 切换侧边栏。窗口宽度不足以在不缩小棋盘的前提下并排放下侧边栏时，侧边栏改以浮层打开。

未保存的棋谱，标题会显示 `•`。已保存的棋谱用文件名；新棋谱先用 `黑方 vs 白方`，其次用赛事名，最后才是 `未命名`。状态副标题只在有内容要报告时出现。

用导航栏上的**编辑工具**，或主菜单 → *视图*，展开编辑工具栏；关掉它会回到落子。棋盘上最后一手有一个红点（若打开了手数，则是红色数字）。SGF 的三角、方块、圆圈、叉号和文字标签都会画出。编辑行为见[复盘](#5-复盘)，快捷键见[快捷键](#9-键盘参考)。

### 棋盘上的鼠标操作

| 操作 | 效果 |
|---|---|
| 左键（落子工具） | 为行棋方下一手真正的棋——吃子、合法性、手数 |
| 右键（落子工具） | 收回当前节点：删除它及其后续，然后回到父节点。撤销会恢复被删的分支；根节点不能删除。这不是菜单 |
| 左键 / 右键（摆黑子或摆白子） | 使用所选颜色 / 相反颜色：在空点放下，替换对方的子，或拿掉同色的子。不吃子，不计手数；标记保留 |
| 用标记工具左键 | 应用该工具；右键无作用 |
| 数子时左键 | 切换该棋块的死活 |
| 滚轮 | 后退 / 前进一手，不删除任何内容 |
| 悬停在候选手标上 | 预览它的变化。非落子工具会清掉这个预览 |
| 悬停在交叉点上（落子或摆子工具） | 在左键会落子的地方显示一颗半透明棋子：合法点上是行棋方，空点上是摆子颜色。对局中只在轮到你时出现 |

## 4. 分析局面

<kbd>Space</kbd> 在当前局面开始或停止实时分析；跳转会开始一次新的搜索。实时计算量上限、报告间隔和候选数上限见[设置](#分析)。已存储的分析没有引擎也能看，但每秒计算量只在实时搜索期间出现。

### 读候选手标

```
   ╭───────╮
   │ 54.2  │  行棋方胜率，百分比
   │ +1.8  │  行棋方目差，单位为目
   │ 8.1k  │  计算量——搜索有多少算在这一手
   ╰───────╯
```

棋盘画得太小、放不下时，下面两行会去掉。计算量少于十的一手不画数字。有两手无论搜索多少都保留数字——引擎自己的首选，以及棋谱接下来要走的那一手。

**颜色表示这一手亏多少。标越实，这个判断就越可信。**引擎首选是青色。更差的一手会从薄荷绿、绿走到黄、橙、红——与问题手条所用的暖色相同。损失是引擎自己对胜率和目差的综合判断，不是计算量，也不是名次。计算量少于十是灰色且很淡：未知，不是好也不是坏。首选从不会是灰色。列表顺序为何可能与胜率、目差和计算量不一致，见[候选手顺序与候选手颜色](../dev/CANDIDATE_COLOUR.md)（英文）。

列表里的序号是引擎的名次，不是计算量；它的颜色与标的损失等级一致。

**白框标出棋谱接下来要走的那一手。**停在第 57 手时，带框的标是第 58 手。如果那一手不在候选里——搜索从未到过那里，或它排在**显示候选数**之外——白框会落在一个发暗的空圆上。到了棋谱末尾就没有白框。

**显示候选数**同时限制标和列表行；调大它会重启实时搜索，调小则只重绘。见[范围与默认值](#分析)。

### 候选手列表

默认列是 **#**（引擎名次）、**着手**（点）、**胜率**和**目差**（行棋方视角），以及**计算量**。用主菜单 → *视图* → *损失与先验列*打开**损失**和**先验**，或右键列标题。损失是这一手相对首选亏掉的（已保存的棋谱若没有，则显示 `—`）；先验是原始网络在搜索之前的偏好。先验高而计算量少，表示网络喜欢一手搜索并不认可的棋；先验低而计算量多，表示搜索找到了网络几乎错过的东西。

列表最初按引擎名次排列；排序只改变列表顺序，不改变标、名次数字，也不改变引擎会下的那一手。按 **#** 排序可恢复引擎顺序。选中一行会把该变化钉住，后续报告到来时仍然保持，直到你跳转离开；双击或按 Enter 下出这一手。悬停在列表上方的计算量那一行，可看 KataGo 的终局目差散布；缓存的判断没有搜索速度。

### 预览变化

悬停在任意候选手标上：棋盘会重绘，把该变化从当前局面下完并标上手数。移开后，真实局面回来。不会写入棋谱。

### 叠加显示

两者读的是同一份分析，因此需要一份报告（实时的，或缓存在这一手上的）。首选项 → 常规 → 棋盘 → **叠加显示**是单选：**无**、**地盘**或**策略**。<kbd>o</kbd>、<kbd>y</kbd> 和视图菜单选的是同一个选项；打开一个会关掉另一个。

| 叠加显示 | 键 | 怎么读 |
|---|---|---|
| **地盘** | <kbd>o</kbd> | 按终局时谁预计拥有该点来着色——黑方深、白方浅，颜色越深越确定，不上色表示确实未定。引擎已经放弃的棋块，棋子还在盘上，也会显示为对方地盘 |
| **策略** | <kbd>y</kbd> | 按原始网络在任何搜索之前想在该点下的程度来着色。把它和搜索后的候选手对照，可以看出搜索在哪里不同意直觉 |

### 单次形势判断

<kbd>Ctrl</kbd>+<kbd>E</kbd> 做一次 400 计算量的短搜索，从地盘图推出死子，按本局自己的规则和贴目计数，并把计数显示在 KataGo 自己的黑方视角目差旁边。实时分析开着或关着都可以。

## 5. 复盘

**打开。** <kbd>Ctrl</kbd>+<kbd>O</kbd>、下载按钮箭头菜单里的*打开文件…*，或命令行上的一个文件。如果文件里有多局，对话框会列出它们——对局者、棋盘大小、手数、结果、日期——由你选择。<kbd>Ctrl</kbd>+<kbd>V</kbd> 从剪贴板粘贴棋谱，<kbd>Ctrl</kbd>+<kbd>C</kbd> 把当前棋谱复制出去。SGF 文件里 mirai 读不懂的内容会原样保留并写回，所以其他程序的文件转一圈也不会丢。

**下载棋谱。** 点击分割按钮上**下载棋谱**的那一半，或按 <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>O</kbd>。先在对话框顶部选择服务器，再搜索：

- **野狐**——准确的野狐昵称或数字 UID。列表最多显示最近 200 条公开棋谱，这是该服务固定的历史窗口。不会绕过隐藏自己棋谱的棋手。
- **弈城**——棋手的姓名或昵称，部分匹配，并且要按弈城的写法（韩国职业棋手的名字常用繁体字）。弈城只向外人开放它的赛事棋谱目录，不开放账号自己的对局，所以这里找到的是它公开的职业和赛事对局；列出最新的 200 条匹配。
- **弈客**——昵称、形如 `CGF00001` 的弈客号、数字账号，或职业棋手的姓名。职业棋手的姓名打开弈客的棋手库；昵称打开该会员的线上对局。弈客昵称可以重名：有多人匹配时，对话框会列出他们，每页十位，由你选择。选择会随这次搜索一起保存；要重新选择，先从最近搜索中移除它。列出最近 100 局。

棋谱每页十局；列表下方的箭头翻到较新或较早的对局。每次搜索都连同棋谱列表一起保存：在同一服务器上再次搜索同一个名字，会立即给出服务器当时返回的结果，列表旁的刷新按钮会重新询问。搜索框为空或正在输入时，对话框会列出所选服务器上最近的搜索，和棋谱一样每页十条；选中一项即可查看它的棋谱，或用它的垃圾桶按钮移除。连不上服务器时，已保存的搜索仍会显示它的棋谱；再次打开对话框会恢复上次的搜索和页码。单击某一局，或在它上面按 Enter，就会下载并打开它；在搜索框按 Enter 是搜索。各服务器的方言会在导入时规范化：野狐以四分之一目计的中国规则贴目和写成一串开局节点的让子，弈城自己的棋谱格式及其解说，弈客用中文写的结果。结果没有本地文件：按对局双方命名，例如 `柯洁 vs 申真谞 •`，因此**保存**会询问存放位置。

**同时打开多份棋谱。** mirai 已经在运行时再打开一个文件——从文件管理器，或命令行上另一个 `mirai game.sgf`——会给这份棋谱单独开一个窗口，而不是替换你正在看的内容；一次传入多个文件会各开一个窗口。这些窗口彼此独立，但共用同一个 KataGo：再开一个窗口不会多占 GPU 内存，也不用再等一次启动，使用它的最后一个窗口关闭时引擎才退出。

**跳转。** 用[快捷键](#9-键盘参考)、棋盘滚轮或滑块、胜率图，或棋谱树页。点击胜率图可在主线上定位。

**曲线。** 没有已存储分析的手会留出缺口。一次全盘分析会把它们补上。

**问题手条。** 每手一根，从走出该手的一方来看。只有这一手和它之前的局面都分析过，才会画出条——没分析过的一段是空档，不是失误。

| 损失的胜率 | 条 |
|---|---|
| 不超过 2% | 不画 |
| 2% – 5% | 黄 |
| 5% – 10% | 橙 |
| 超过 10% | 红 |

**全盘分析。** <kbd>Ctrl</kbd>+<kbd>A</kbd> 按**每手计算量**把主线扫一遍（默认 100）。**取消**会保留已经完成的分析；曲线会随着结果陆续补上。**问题手**列表使用已存储的分析，并随棋谱更新。每一行显示行棋者、手数、损失的胜率、实战手，以及若已存储的引擎选择。点击一行跳到那里；折叠列表不会丢掉内容。分析过的棋谱即使没有正在运行的引擎也会显示问题手，但重新扫一次需要有引擎在跑。

**编辑工具。** 棋盘上方的工具栏默认展开；用导航栏上的**编辑工具**或视图菜单隐藏或显示。其中有撤销/重做、**切换行棋方**、落子、摆子和标记。关掉它会回到落子，且不增加一步撤销。对局进行时它保持关闭且不可用。

**变化与棋谱树。** 在终局之前落子会走出一条变化，原来的后续仍然保留。在棋谱树里，主线向下延伸，变化在右侧；空心节点是开局或摆子局面，节点上的一杠表示停一手，当前节点有一个圆环。点击节点跳转；右键节点可*设为主线*（仅在主线之外提供）和*删除分支*（开局节点不提供）。

| 操作 | 做法 |
|---|---|
| 把一条变化提升为主线 | 在棋谱树里右键它的节点 → *设为主线*，或对当前节点按 <kbd>Ctrl</kbd>+<kbd>↑</kbd> |
| 删除这一手及其后的一切 | 在落子工具下右键、<kbd>Delete</kbd>，或在棋谱树里右键它的节点 → *删除分支* |
| 撤销 / 重做上一次编辑 | <kbd>Ctrl</kbd>+<kbd>Z</kbd> / <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Z</kbd> |

开局不能删除。在已有着手或后续的节点上摆子会新增一条变化；之后的摆子点击留在这条新的末端。

**棋子工具。** 落子工具的图标显示行棋方。**切换行棋方**（旁边的 ⇄ 按钮，或 <kbd>t</kbd>）把着手交给另一方；棋谱里记为 `PL`。选择摆黑子或摆白子，可以放置、拿掉或替换棋子，而不改变行棋方。右键用相反的颜色。

**注释与标记。** 在**注释**里编辑某一手的注释。离开该手、离开输入框或保存棋谱时写入；这一次输入算一步撤销。再点一次同一标记会去掉它；换一种标记会替换它。标签文字为空则删除该标签。擦除标记只去掉标记和标签，不去掉棋子。

## 6. 对局

<kbd>Ctrl</kbd>+<kbd>N</kbd> 或**新对局**按钮。若只想把当前棋谱清成空盘、而不开始与引擎的对局，用主菜单 → *清空棋盘*，或 <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>N</kbd>。棋盘大小、规则和贴目保留；棋子、注释和文件路径不保留。

### 新对局对话框

选择棋盘、规则、执子颜色和可选的棋钟，然后**开始对局**。*双方（无引擎）*让你下双方的棋，并隐藏引擎棋力。只要棋钟在走，就会限制引擎的思考时间，与棋力无关。规则和棋力选择会成为下一局的默认值。如果当前权重没有已保存的拟人档位，这一局改用计算量，但不改已保存的设置。

棋盘、棋钟、规则和棋力的选项与默认值见[设置参考](#对局)。

### 对局进行中

点击空点落子。引擎思考时（状态栏显示 `思考中… 计算量 3.4k`）、轮到引擎但卡住时，以及终局之后，棋盘只读。如果引擎无法落子——没有引擎在运行，或搜索失败——状态栏会说明原因。对局栏里的**重试**会再问一次；启动引擎也会自动再问。**撤销**和**认输**仍然可用，棋盘保持只读，直到轮到你。对局进行时编辑器被强制关闭，编辑开关不可用，普通右键被忽略，重做不可用，<kbd>Ctrl</kbd>+<kbd>Z</kbd> 收回的是整轮交换，而不是一次文档编辑。*双方（无引擎）*仍然是一局：你下双方的棋，没有引擎着手，也没有**认输**，编辑保持关闭，直到这一局结束。

对局中也能退回去查看之前的棋。棋钟和引擎仍在最新落子处继续，不会跟随浏览位置；引擎回应后，棋盘会跳到新着手。不能在较早的局面落子；**撤销**收回的是最新一轮交换，而不是正在浏览的节点。

**棋钟**出现在棋盘导航下方的对局栏里，不在标题栏。黑方是 `●`，白方是 `○`，行棋方用强调色显示。

| 类型 | 行为 |
|---|---|
| 包干计时 | 基本用时倒数；到零即超时负 |
| 费舍尔加秒 | 每完成一手，加上每手加秒 |
| 读秒 | 先走基本用时；用完后进入第一次读秒，棋钟重置为该次时长。括号里的数字是剩余次数，含你正在用的这一次。在一次读秒内走完，该次完整重置。次数用尽后再超时，即超时负 |

基本用时为 0 的读秒局会直接进入第一次读秒。基本用时为 0 的费舍尔加秒局，开局棋钟上就有一次加秒。

| | |
|---|---|
| **停一手** | <kbd>p</kbd>，或对局栏按钮。连续两次停一手结束对局并进入数子 |
| **重试** | 对局栏按钮，仅当引擎这一手卡住时出现。再要一次着手 |
| **撤销** | <kbd>Ctrl</kbd>+<kbd>Z</kbd>，或对局栏按钮，收回整轮交换——引擎的一手和你的一手——取消正在进行的搜索，并精确恢复双方棋钟 |
| **认输** | 对局栏按钮，仅在你与引擎对弈时出现。故意不设快捷键。*引擎*会在胜率连续低于**认输阈值**达**认输连续次数**个回合、并且手数超过棋盘交叉点数的四分之一时自行认输 |

对局中实时分析仍然可用，会把引擎自己的思考显示出来。想公平对弈就把它关掉。

### 数子

连续两次停一手之后，mirai 会短暂搜索，根据地盘估计死子，并按本局规则和贴目计数。数子视图会把死子变淡，并用归属方颜色的方块标出地盘。

**计数显示后，点击任意棋块，可在死活之间切换。**状态栏显示 `正在数子…` 时棋盘只读。计数在本地更新，不再询问引擎；用来改正判错的棋块或双活。**关闭**会继续计数；**复盘**结束这一局，以便编辑棋谱；**全盘分析**结束这一局并开始全盘分析。

认输或超时会自行确定胜负；mirai 仍会计数，并显示如果数子会是什么结果。

## 7. 使用远程引擎

`mirai-server` 把 KataGo 留在有 GPU 的台式机上，笔记本通过网络连接。两台机器都在你的局域网里时，分析就留在这个网络上。连接使用 QUIC，因此防火墙要放行 UDP，而不是 TCP。

### 在台式机上

**1. 生成令牌**——一长串秘密，笔记本用它证明自己被允许进入。

```
mirai-server --generate-token
```

**2. 复制带注释的示例**，不要凭记忆写配置：

```
mkdir -p ~/.config/mirai
cp crates/mirai-server/server.example.toml ~/.config/mirai/server.toml
chmod 600 ~/.config/mirai/server.toml
```

若设置了该变量，路径就是 `$XDG_CONFIG_HOME/mirai/server.toml`。把生成的令牌贴进 `[[token]]`（示例中的全零令牌会被拒绝），并设置 KataGo 程序和权重。令牌是密钥，请只允许自己的账号读取配置文件；如果其他用户可读，服务器会警告。相对路径相对于配置文件所在目录解析。令牌超过 256 字节时，服务器不会启动。

**3. 启动。**

```
mirai-server --config ~/.config/mirai/server.toml
```

它会先加载每一个已配置的 KataGo，然后才对外服务——大权重要几秒，如果第一次查询才懒加载，看起来就像卡住——接着打印**证书指纹**。让它留在屏幕上。`mirai-server --print-fingerprint` 可以随时再打印一次。某一个引擎启动失败会记入日志并跳过；只有一个都没起来时，服务器才退出。

如果运行中的 KataGo 后来退出，新请求会失败，直到服务器在后台重新启动该引擎；已有请求不会重放。

**4. 在台式机的防火墙上开放 UDP 端口 9678。**示例监听 `0.0.0.0:9678`；`127.0.0.1` 则只有本机能连。

一台服务器用同一个 KataGo 服务多个客户端；不会为每个人再启动一份。KataGo 同时分析 `analysis_threads` 个局面，其余排队：引擎落子和实时分析排在全盘分析前面，其余先到先得。`max_subs`（默认 64）只限制一个令牌同时排队或运行的请求数。

### 在笔记本上

在**首选项 → 引擎 → 添加远程引擎**中，填写名称、服务器地址（`mirai://192.168.1.10:9678`）和生成的令牌。如果服务器上有多个引擎，填写其中一个的名称；否则把**引擎名称**留空，使用第一个。

按**测试连接**，把**信任此服务器？**里的指纹与服务器打印的那一个对照。一致就按**信任**，然后**保存配置**，并从引擎按钮选中它。不一致就取消，并检查网络和地址。只有在你信任了相符的指纹之后，令牌才会送出。选中尚未固定指纹的配置会问同样的问题；取消则保持未连接。更改服务器地址会清除原来固定的指纹。

### 如果 mirai 之后拒绝连接

与已固定指纹不符的证书会被直接拒绝，不是可以点过去的警告。

| 原因 | 怎么办 |
|---|---|
| 服务器的 `cert.pem`/`key.pem` 被删除或重新生成，或服务器重装了 | 这是预期情况。用 `mirai-server --print-fingerprint` 取得新值，然后在笔记本上编辑远程配置 → **测试连接** → 核对可选中的指纹 → **信任** → **保存配置** |
| 服务器上什么都没改 | 不要信任。有东西在拦截连接；检查网络和地址 |

其他连接失败时，检查 `mirai://` 地址和 UDP 9678、服务器是否监听了 `127.0.0.1` 以外的地址，以及 `[[token]]` 的值是否完全一致。没有令牌块时，服务器能启动，但会拒绝每一个客户端。

## 8. 设置参考

首选项会自动保存更改。本节是客户端设置和手改配置的参考。

### 引擎

| 设置 | 默认值 | 说明 |
|---|---|---|
| 引擎配置 | 若找到 KataGo 则为一个 | 单选按钮表示当前引擎；铅笔编辑，垃圾桶删除 |
| *本地* 名称 / KataGo 程序 / 神经网络模型 | — | 两条路径都必须存在才能保存；模型行的列表按钮列出所有已发现的权重，文件夹按钮可选任意其他文件 |
| *本地* 分析配置 | 由 mirai 管理 | *自定义文件*会显示配置行，其列表按钮列出所有已发现的分析配置；调优设置来自该文件，但可以覆盖两个线程数 |
| *本地* 并行局面数 | 0，即 4 | `numAnalysisThreads`：同时搜索的局面数。设为 4，全盘分析与移动光标就不会互相排队 |
| *本地* 每局面线程数 | 0，即 16 | `numSearchThreadsPerAnalysisThread`：单个局面搜得多深。多核 CPU 上可以提高，但超过 16 之后收益下降 |
| *本地* GPU 批大小 | 0，即 64 | `nnMaxBatchSize`。最好至少是局面数 × 线程数。选了自定义配置时隐藏 |
| *本地* 神经网络缓存 | 0，即 20 | `nnCacheSizePowerOfTwo`：缓存 2^20 次求值，预热后大约 3 GiB。0 是默认值；下一档是 14。选了自定义配置时隐藏 |
| *本地* 自动调优 | 关 | **调优…**测量所选程序和权重，更新三行性能设置，并等你按**保存配置**后才应用。仅限由 mirai 管理的配置 |
| *远程* 服务器地址 / 令牌 / 引擎名称（可选） | — / — / 空 | 引擎名称为空表示使用服务器的第一个引擎 |
| *远程* 已固定指纹 | 未固定 | 只读；由**测试连接**和**信任**写入 |

在**由 mirai 管理**下，这四行里的 `0` 表示 mirai 自己的默认值；在*自定义文件*下，它表示*保留文件里的值*，行的副标题也会改成这样说。由 mirai 管理的配置设置上面的四个值。自定义配置保留其调优设置，但非零的线程数会覆盖文件里的值。两种模式下，mirai 都固定以黑方视角报告，并控制日志设置。使用自定义配置时，请明确设置 `nnCacheSizePowerOfTwo`：KataGo 分析引擎的默认值是 2^23，预热后大约占 24 GiB。

自动调优故意做成手动、且按每个配置单独进行：改路径或打开首选项都不会开始测量。先等引擎启动完成，并先结束或取消全盘分析。关掉其他 mirai 窗口；调优进行中再开一个窗口会中止这次测量。调优会暂时停掉本窗口平时用的引擎，以免另一次搜索或第二份权重影响结果，或耗尽 GPU 内存。每个候选设置都会启动一次 KataGo，因此首次运行时的 OpenCL 内核调优可能让这次测量比通常的一两分钟更久。**停止调优**取消当前查询，已保存的配置保持不变。成功后，核对测得的局面数、线程数和批大小，再按**保存配置**写入并启用。神经网络缓存不会被改动。

### 设置文件

`~/.config/mirai/config.toml`（严格来说是 `$XDG_CONFIG_HOME`）。纯文本，在 mirai 关闭时可以手改。文件缺失没有关系；格式错误时，mirai 会退回一份填好的首次运行配置，而不是带着半份配置启动。保存不会修复那个文件：错误会被报告，文本保持原样。平时用首选项来编辑。手写文件只需要写上你正在添加的配置；省略的分析、对局和显示设置键都用上面表格里的默认值。

本地配置：

```toml
active_engine = "local-default"

[[engine_profile]]
name = "local-default"
kind = "local"
katago = "/path/to/katago"
model = "/path/to/model.bin.gz"
```

远程配置，可以写在同一个文件里，也可以代替本地配置。`cert_sha256` 在你按**信任**之后写入；不要自己编造。

```toml
active_engine = "desktop"

[[engine_profile]]
name = "desktop"
kind = "remote"
url = "mirai://192.168.1.10:9678"
token = "…"
```

除非服务器有多个引擎、而你想按名称指定一个，否则不要写 `engine`。自动保存、KataGo 的日志和生成的分析配置都在 `$XDG_DATA_HOME/mirai/` 下。

对局中 <kbd>Ctrl</kbd>+<kbd>Z</kbd> 收回双方的上一手；复盘时它撤销上一次编辑——放下一子、一个标记、一次注释提交——而不是每一次按键。<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Z</kbd> 重做（对局中不可用）。同一张表也在程序里：主菜单 → *键盘快捷键*。

**输入优先。**注释、标签或搜索框获得焦点时，用来输入和编辑的键都交给它：字母、Space、方向键、<kbd>Delete</kbd>，以及 <kbd>Ctrl</kbd>+<kbd>A</kbd>/<kbd>C</kbd>/<kbd>V</kbd>/<kbd>Z</kbd>——因此注释里的 <kbd>p</kbd> 是字母，不是停一手，<kbd>Ctrl</kbd>+<kbd>Z</kbd> 撤销的是输入。点击棋盘、胜率图或棋谱树，把这些键交还。<kbd>Ctrl</kbd>+<kbd>S</kbd>、<kbd>Ctrl</kbd>+<kbd>O</kbd>、<kbd>Ctrl</kbd>+<kbd>N</kbd>、<kbd>Ctrl</kbd>+<kbd>E</kbd> 和 <kbd>F9</kbd> 在任何地方都有效。按钮获得焦点时，<kbd>Space</kbd> 会按下该按钮，与 GNOME 各处一样。

没有专用快捷键：切换引擎配置、*首选项*、*键盘快捷键*、*关于 mirai* 和*编辑工具*。它们仍可用标准的键盘焦点到达。

## 10. mirai 写入的文件

| 路径 | 内容 |
|---|---|
| `~/.config/mirai/config.toml` | 设置和引擎配置，含远程令牌，因此写成只有你能读（`0600`；若由 mirai 创建该目录，则为 `0700`） |
| `~/.local/share/mirai/autosave-*.sgf` | 每个打开的窗口正在看的棋谱，一个窗口一个文件 |
| `~/.local/share/mirai/kifu-searches.json` | 在野狐、弈城和弈客上最近 20 次搜索及其棋谱列表；再次搜索同一个名字时直接从这里给出，不再询问服务器 |
| `~/.local/share/mirai/katago-logs/` | KataGo 自己的日志，每次引擎启动一个文件，以及生成的 `katago-analysis-*.cfg`；没有 `log_dir` 的 `[[engine]]`，`mirai-server` 的也在这里。创建时为私有。若生成配置所用的目录由其他用户拥有或可写，或者通往它的某一级目录如此（`/tmp` 这类粘滞位目录除外），则会拒绝 |
| `~/.config/mirai/server.toml` | `mirai-server` 的设置，在运行它的那台机器上 |

（若设置了 `$XDG_CONFIG_HOME` 和 `$XDG_DATA_HOME`，则遵从它们。）

自动保存每 30 秒一次，且只在有值得保留的内容时进行——一手棋、一颗摆子、一个标记、明确的行棋方，或一条注释；空盘从不保存。关闭窗口会**删除**它的自动保存，因此下次启动时还在的文件，就是崩溃留下的，mirai 提议恢复的就是它。自动保存不是你的文件：恢复它并不会让一次普通的保存写到那里。KataGo 的日志会累积，可以随时删除，生成的分析配置也一样——内容将要变化时，mirai 会重新写一份。保存的搜索可以删除；下次查询会重新开始记录。除此之外不写任何东西；你自己的 KataGo 安装、权重，以及你提供的任何分析配置，都不会被修改。

## 11. 疑难解答

### 引擎无法启动

如果配置失败，引擎按钮退回“无引擎”，请到**首选项 → 引擎**检查程序和权重是否还在。它必须是 KataGo 的 JSON 分析引擎，而不是 GTP（[安装](#1-安装)）。GPU 报错或权重不匹配时，阅读 `~/.local/share/mirai/katago-logs/`；使用彼此匹配的程序和权重。

### 首次启动需要数分钟

可能以 `katago did not answer within 180s` 结束。

*原因：* OpenCL 版 KataGo 在给定棋盘尺寸上第一次运行时，会针对你的 GPU 自行调优。这确实要几分钟，而且只此一次。

*处理：* 等它跑完，同时看 `~/.local/share/mirai/katago-logs/`。如果确实超时，在终端里运行一次 `katago benchmark -model … -config …`，让调优在没有时限的情况下完成；之后 mirai 几秒就能启动。远程引擎则在服务器上做同样的事。

### 看不到分析

按 <kbd>Space</kbd> 开始[实时分析](#4-分析局面)。如果没有配置，用分析页上的**首选项**。已存储的结果没有引擎也能显示；叠加显示至少需要一份报告。如果搜索很快停下，或候选手缺失，到[设置](#分析)里检查**最大计算量**和**显示候选数**。等待第一份报告时，页面显示*分析中…*；引擎启动错误也会出现在那里。

### 远程连接被拒绝

URL、UDP、令牌和指纹的检查见[远程引擎的设置与连接失败](#7-使用远程引擎)。

### “mirai 未能正常退出”

有窗口关闭时没有清掉自动保存。**恢复**把它作为未命名棋谱载入（第一次**保存**会询问位置）；**丢弃**则删除它。如果当时开着多个窗口，新窗口会提供这些自动保存，最近的在前。

### 其他程序的 SGF 看起来不对

| 现象 | 原因 / 处理 |
|---|---|
| 多局文件只打开了一局 | 重新打开，并在[棋谱列表](#5-复盘)里另选一局 |
| 曲线是空的 | 做一次全盘分析，然后打开[在 SGF 中保存分析](#分析)以保留它们 |
| 有些标注没有画出来 | 不支持的属性仍会保留，即使 mirai 不显示它们 |
| 结果或贴目看起来不对 | 使用的是文件里写明的值 |
| 完全打不开 | 不是 SGF，或已损坏；通知会指出问题 |
